5 年经验 Java 后端·Java SE 核心知识点背诵清单

这份文档不是面试题集，而是结构化的知识要点汇总，旨在帮助候选人快速复习和背诵核心概念、参数含义、底层流程及关键结论。

范围说明：仅包含 Java SE 部分，严禁包含 Spring、MySQL、Redis 等框架或中间件内容。

一、JVM 深度核心

🔑 ⭐⭐⭐ JVM 内存区域划分

  • 核心定义：JVM 将运行时数据区划分为线程私有和线程共享两大部分。
  • 底层原理：
    • 线程私有：程序计数器（PC Register）、虚拟机栈（VM Stack）、本地方法栈（Native Method Stack）
    • 线程共享：堆（Heap）、方法区（Method Area）
  • 关键参数：
  • 常见坑点：⚠️ 栈溢出（StackOverflowError）vs 堆溢出（OutOfMemoryError）；元空间溢出（Metaspace OOM）
  • 新旧对比：JDK1.8 移除永久代（PermGen），改为元空间（Metaspace），使用本地内存

🔑 ⭐⭐⭐ 垃圾回收算法

  • 核心定义：自动管理内存，回收不再使用的对象。
  • 底层原理：
    • 标记 - 清除（Mark-Sweep）：标记存活对象，清除未标记对象；产生内存碎片
    • 标记 - 整理（Mark-Compact）：标记后整理到一端；无碎片，适合老年代
    • 复制（Copying）：存活对象复制到另一区域；无碎片，适合新生代（8:1:1）
    • 分代收集：新生代（Young）+ 老年代（Old）+ 元空间（Metaspace）
  • 关键参数：
  • 常见坑点：⚠️ 动态对象年龄判定（同年龄对象总和 > Survivor 50% 直接晋升）；长期存活对象自动晋升

🔑 ⭐⭐⭐ G1 垃圾收集器

  • 核心定义：Java 9 默认收集器，基于 Region 分区，实现可预测停顿时间。
  • 底层原理：
    • 堆划分为多个 Region（默认 2048 个）
    • Region 类型：Eden、Survivor、Old、Humongous（大对象）
    • 维护 Remembered Set 记录跨 Region 引用
    • 基于回收价值排序（Garbage First）
  • 关键参数：
  • 常见坑点：⚠️ Humongous 对象（超过 Region 50%）直接分配在老年代；Mixed GC 不是 Full GC
  • 新旧对比：CMS（Mark-Sweep，不可预测停顿）vs G1（Mark-Compact，可预测停顿）

🔑 ZGC 垃圾收集器

  • 核心定义：超低延迟收集器，停顿时间 < 10ms，支持 TB 级堆。
  • 底层原理：
    • 基于染色指针（Colored Pointers）
    • 读屏障（Load Barriers）实现并发标记和整理
    • 分页内存管理（4MB 页）
  • 关键参数：
  • 常见坑点：⚠️ Java 15+ 才适合生产环境；Java 21 引入分代 ZGC（Generational ZGC）
  • 新旧对比：G1（停顿 200ms 内）vs ZGC（停顿<10ms）

🔑 ⭐⭐⭐ 类加载双亲委派模型

  • 核心定义：类加载器收到请求时，首先委托给父加载器，只有父加载器无法加载时才自己加载。
  • 底层原理：
    • 类加载器层次：Bootstrap → Extension → Application → Custom
    • loadClass() 方法实现双亲委派
    • 避免核心 API 被篡改，保证类唯一性
  • 关键流程：
    1. 检查类是否已加载
    2. 委托父加载器加载
    3. 父加载器无法加载，调用 findClass()
  • 常见坑点：⚠️ SPI 机制（JDBC）打破双亲委派，使用线程上下文类加载器（Thread.currentThread().getContextClassLoader()）
  • 新旧对比：JDK 9+ 模块系统（JPMS）部分替代双亲委派

🔑 对象头结构

  • 核心定义：Java 对象在内存中的元数据结构。
  • 底层原理：
    • Mark Word（64 位 JVM）：存储对象哈希码、GC 分代年龄、锁标志位
    • Klass Pointer：指向类元数据的指针
    • 数组长度（仅数组对象）
  • 关键数据：
    • 普通对象：8 字节（Mark Word）+ 4 字节（Klass Pointer）= 12 字节（对齐后 16 字节）
    • 数组对象：12 字节 + 4 字节（长度）= 16 字节（对齐后 24 字节）
  • 常见坑点：⚠️ 对象对齐（8 字节对齐）；开启偏向锁会增加对象头开销

二、JUC 并发编程

🔑 ⭐⭐⭐ volatile 关键字

  • 核心定义：保证变量可见性和禁止指令重排，不保证原子性。
  • 底层原理：
    • 基于Lock 前缀指令触发 CPU 缓存一致性协议（MESI）
    • 插入内存屏障（LoadLoad, StoreStore, LoadStore, StoreLoad）
    • 强制从主内存读取，写入后立即刷新到主内存
  • 关键参数：无特定参数，但需注意 64 位 long/double 在非 volatile 下的非原子读写问题
  • 常见坑点：⚠️ i++ 操作即使 volatile 也不安全，需配合 AtomicInteger 或 synchronized
  • 新旧对比：JDK 1.5 引入，之前仅靠 synchronized

🔑 ⭐⭐⭐ CAS 与原子类

  • 核心定义：Compare-And-Swap，无锁实现原子操作。
  • 底层原理：
    • 三个参数：内存地址、预期值、新值
    • 基于 CPU 的 CMPXCHG 指令
    • ABA 问题：使用版本号或 AtomicStampedReference 解决
  • 关键类：
    • AtomicInteger、AtomicLong、AtomicReference
    • AtomicIntegerFieldUpdater（原子更新字段）
  • 常见坑点：⚠️ 自旋消耗 CPU；长自旋可能影响性能；ABA 问题
  • 新旧对比：synchronized（悲观锁）vs CAS（乐观锁）

🔑 ⭐⭐⭐ AQS（AbstractQueuedSynchronizer）

  • 核心定义：JUC 并发包的基石，实现锁和同步器的框架。
  • 底层原理：
    • state 变量（volatile int）：同步状态
    • CLH 双向队列：管理等待线程
    • 线程通过 CAS 尝试修改 state，失败则加入队列
  • 关键流程（tryAcquire）：
    1. CAS 尝试获取锁
    2. 失败后封装成 Node 加入队列
    3. LockSupport.park() 挂起线程
    4. 前驱节点释放锁后唤醒
  • 关键参数：无
  • 常见坑点：⚠️ 公平锁 vs 非公平锁（hasQueuedPredecessors()）；可重入机制
  • 新旧对比：ReentrantLock（基于 AQS）vs synchronized（JVM 层面）

🔑 ⭐⭐⭐ Synchronized 锁升级过程

  • 核心定义：JDK 1.6+ 优化，锁从低级别向高级别升级。
  • 底层原理：
    • 偏向锁：单线程访问，无同步开销
    • 轻量级锁：多线程交替访问，CAS 自旋
    • 重量级锁：多线程竞争激烈，阻塞线程
  • 升级流程：
    1. 无锁 → 偏向锁（Mark Word 记录线程 ID）
    2. 偏向锁 → 轻量级锁（CAS 替换对象头，自旋等待）
    3. 轻量级锁 → 重量级锁（自旋失败，膨胀为重量级锁）
  • 关键参数：
  • 常见坑点：⚠️ 批量重偏向和批量撤销；JDK 15+ 默认禁用偏向锁

🔑 ⭐⭐⭐ ThreadLocal 原理与泄漏

  • 核心定义：线程本地变量，每个线程独立副本。
  • 底层原理：
    • ThreadLocalMap 存储键值对
    • Key 是弱引用（WeakReference），Value 是强引用
    • 哈希冲突使用开放寻址法（线性探测）
  • 泄漏根因：
    • ThreadLocal 对象被 GC 回收后，Key 变为 null
    • Value 仍存在，线程长期存活（如线程池）导致内存泄漏

  • 常见坑点：⚠️ 必须在 finally 中调用 remove()；线程池场景慎用

🔑 ⭐⭐⭐ 线程池七大参数

  • 核心定义：ThreadPoolExecutor 构造函数参数。
  • 底层原理：
  • 执行流程：
    1. 核心线程数未满 → 创建核心线程
    2. 核心线程已满 → 加入队列
    3. 队列已满 → 创建非核心线程
    4. 最大线程数已满 → 触发拒绝策略
  • 拒绝策略：
    • AbortPolicy：抛出异常（默认）
    • CallerRunsPolicy：调用线程执行
    • DiscardPolicy：丢弃任务
    • DiscardOldestPolicy：丢弃最旧任务
  • 常见坑点：⚠️ 禁止使用 Executors 工具类创建（OOM 风险）；队列建议使用有界队列

🔑 CompletableFuture 异步编排

  • 核心定义：Java 8 引入的异步编程工具，支持链式调用和组合。
  • 底层原理：
    • 基于事件驱动和回调机制
    • 内部使用 ForkJoinPool.commonPool()（默认）
    • 支持非阻塞式结果获取
  • 关键 API：
    • supplyAsync()：异步执行有返回值任务
    • thenApply()：转换结果
    • thenAccept()：消费结果
    • thenCombine()：合并两个 Future
    • allOf() / anyOf()：等待所有/任意完成
  • 常见坑点：⚠️ 异常处理（exceptionally()、handle()）；避免嵌套 Future（使用 thenCompose()）

🔑 伪共享与 Cache Line 优化

  • 核心定义：多核 CPU 缓存一致性问题导致的性能下降。
  • 底层原理：
    • CPU 缓存以 Cache Line 为单位（通常 64 字节）
    • 多个变量在同一 Cache Line，一个变量修改导致其他变量缓存失效
    • 使用 @Contended 注解填充缓存行

三、集合源码精髓

🔑 ⭐⭐⭐ HashMap（JDK 1.8）

  • 核心定义：基于数组 + 链表 + 红黑树的键值对存储结构。
  • 底层原理：
    • 数组：Node<K,V>[] table
    • 链表：解决哈希冲突
    • 红黑树：链表长度 > 8 且数组长度 > 64 时转换
  • 关键参数：
    • 默认初始容量：16（必须是 2 的幂）
    • 负载因子：0.75
    • 树化阈值：8（链表转红黑树）
    • 退化阈值：6（红黑树转链表）
  • 扩容机制：
    • 阈值 = 容量 × 负载因子
    • 扩容为原来的 2 倍
    • rehash：高位为 0 在原位，为 1 在”原位置 + 旧容量”
  • 常见坑点：⚠️ JDK 1.7 扩容死循环（头插法）vs JDK 1.8 尾插法；非线程安全
  • 新旧对比：JDK 1.7（数组 + 链表，头插法）vs JDK 1.8（数组 + 链表/红黑树，尾插法）

🔑 ⭐⭐⭐ ConcurrentHashMap（JDK 1.8）

  • 核心定义：高并发场景下的线程安全 Map。
  • 底层原理：
    • 废弃 Segment，改用 Node 数组
    • CAS + synchronized 保证并发安全
    • 锁粒度：桶（Node）级别
  • 关键参数：同 HashMap
  • 并发机制：
    • 插入节点：CAS 尝试，冲突时 synchronized 锁桶首节点
    • 扩容：多线程协同（Transfer 任务）
    • size 统计：LongAdder 类似的分段累加
  • 常见坑点：⚠️ 不支持 null 键值；迭代器弱一致性（不抛 ConcurrentModificationException）
  • 新旧对比：JDK 1.7（Segment 分段锁）vs JDK 1.8（CAS + synchronized）

🔑 ArrayList 扩容机制

  • 核心定义：动态数组，容量不足时自动扩容。
  • 底层原理：
    • 底层数组：Object[] elementData
    • 扩容：新容量 = 旧容量 × 1.5
    • 数组拷贝：Arrays.copyOf()
  • 关键参数：
    • 默认初始容量：10
    • 扩容倍数：1.5 倍
  • 扩容流程：
    1. 检查容量是否足够
    2. 计算新容量（oldCapacity + (oldCapacity >> 1)）
    3. 数组拷贝
  • 常见坑点：⚠️ 频繁扩容影响性能；初始化时指定合适容量

🔑 Fail-Fast 机制

  • 核心定义：集合在迭代过程中被修改时，快速失败。
  • 底层原理：
    • 维护 modCount 计数器
    • 迭代器记录 expectedModCount
    • 每次迭代检查两者是否相等

  • 常见坑点：⚠️ 并发修改异常（ConcurrentModificationException）；使用 CopyOnWriteArrayList 或 Iterator.remove() 避免

四、IO/NIO 模型

🔑 ⭐⭐⭐ BIO/NIO/AIO 区别

  • 核心定义：三种 IO 模型，分别对应同步阻塞、同步非阻塞、异步非阻塞。
  • 底层原理：
    • BIO：同步阻塞 IO，一个连接一个线程
    • NIO：同步非阻塞 IO，多路复用（Selector）
    • AIO：异步非阻塞 IO（NIO.2），基于事件和回调
  • 关键对比：
    模型 阻塞方式 适用场景
    BIO 阻塞 连接数少且固定
    NIO 非阻塞 高并发、短连接
    AIO 异步 高并发、长连接
  • 常见坑点：⚠️ NIO 编程复杂度高；AIO 生态不成熟

🔑 Selector 多路复用

  • 核心定义：单个线程监控多个 Channel 的 IO 事件。
  • 底层原理：
    • 基于 epoll（Linux）/ kqueue（BSD）/ select（Windows）
    • 注册 SelectionKey（OP_READ、OP_WRITE、OP_CONNECT、OP_ACCEPT）
    • 轮询就绪的 SelectionKey
  • 关键代码：
  • 常见坑点：⚠️ 惊群效应；空轮询 bug（JDK epoll bug）

🔑 ⭐⭐⭐ 零拷贝（Zero Copy）

  • 核心定义：减少数据在内核态和用户态之间的拷贝次数。
  • 底层原理：
    • 传统 IO：4 次拷贝 + 4 次上下文切换
    • 零拷贝：2 次拷贝 + 2 次上下文切换
  • 四种实现方式：
    1. mmap + write：内存映射，减少 1 次拷贝
    2. sendfile：内核空间拷贝，减少 2 次拷贝
    3. sendfile + sendTo：Linux 2.4+，无 CPU 拷贝
    4. FileChannel.transferTo()：Java 封装
  • 常见坑点：⚠️ 零拷贝适合大文件传输；小文件效果不明显

🔑 Netty 核心组件

  • 核心定义：高性能异步 IO 框架，基于 NIO。
  • 底层原理：
    • EventLoopGroup：线程池（Boss/Worker）
    • Channel：网络连接
    • ChannelPipeline：责任链模式
    • ChannelHandler：业务逻辑处理器
    • ByteBuf：高性能缓冲区
  • 关键特性：
    • Reactor 模型（主从多线程）
    • 零拷贝（内部实现）
    • 内存池（Pooled ByteBuf）
  • 常见坑点：⚠️ 内存泄漏（ReferenceCounted 需手动释放）；线程模型设计

五、Java 新特性（17/21）

🔑 ⭐⭐⭐ 虚拟线程（Virtual Threads）

  • 核心定义：Java 21 最大特性，轻量级线程，单机支持百万级并发。
  • 底层原理：
    • 载体线程（Carrier Thread）：平台线程作为载体
    • 挂载/卸载：虚拟线程阻塞时卸载，IO 完成后重新挂载
    • 调度器：JVM 内部的 ForkJoinPool 调度
    • 连续栈：虚拟线程栈可动态扩展
  • 关键参数：
  • 适用场景：高并发 IO、大量阻塞调用；不适用计算密集型任务
  • 新旧对比：
    维度 平台线程 虚拟线程
    映射 1:1 映射到 OS 线程 M:N 映射到 OS 线程
    内存占用 ~1MB 栈空间 ~1KB 初始栈
    阻塞行为 阻塞 OS 线程 卸载到载体线程
  • 常见坑点：⚠️ Pinning 问题（synchronized 块或 native 方法中无法卸载）；不应使用有界线程池

🔑 Record 类

  • 底层原理：

🔑 Switch 模式匹配

  • 底层原理：

🔑 ZGC 低延迟特性

  • 核心定义：超低延迟垃圾收集器，停顿时间 < 1ms（Java 21）。
  • 底层原理：
    • 分代回收（Generational ZGC，Java 21）

总结

这份背诵清单涵盖了 5 年经验 Java 后端工程师必须掌握的Java SE 核心知识点：

  1. JVM 深度核心：内存区域、GC 算法、G1/ZGC、类加载、OOM 排查
  2. JUC 并发编程：volatile、CAS、AQS、锁升级、ThreadLocal、线程池
  3. 集合源码精髓：HashMap、ConcurrentHashMap、ArrayList、Fail-Fast
  4. IO/NIO 模型：BIO/NIO/AIO、Selector、零拷贝、Netty
  5. Java 新特性：虚拟线程、Record、Switch 模式匹配、ZGC
